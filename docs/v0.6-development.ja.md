# v0.6 開発計画と進捗

更新日：2026-11-25（日本時間）。対象は `dev/v0.6` の開発系列。段階ごとの完了条件は[実装順と受入条件](proposals/2026-11-10-rust-wp-core-v0.6/implementation-and-validation.ja.md)を参照する。

**次の統合目標は、常駐 HTTP の匿名ホーム・404で現行の PHP 互換境界を検証すること。** Ubuntu のローカル MySQL／MariaDB では、現行の Rust Dispatcher と実 `WP_Hook` オーバーレイによるインストールと別インスタンスからの読み取りを確認した。最初の公開コアでは既存 PHP テーマと `pre_get_posts` を使うプラグインを Rust Query で動かす。

## 現在の到達点

Ubuntu 24.04 で、PHP-WASIX 8.5.12 上の WordPress 7.1.3 をローカル MariaDB 11.8.9 に新規インストールした。別の PHP-WASIX インスタンスからの読み取りも CGI 200 で完了した。両方で実 `WP_Hook` の `option_blogname` を Rust Dispatcher に渡し、2つのコールバックが順番に実行され、`RP Bootstrap Fixture|first|second` を返した。ネイティブ比較との一致、WordPress の12テーブル、DB の切断と正常停止も確認した。Ubuntu 配布の MariaDB 10.11.14 でも同じ検査が通った。[実行証跡](../experiments/php-wasix-wp-bootstrap-probe/evidence/linux-local-wp-boot-mariadb.json) · [再実行手順](demo-full-wp-bootstrap-hook.ja.md)

| 対象 | 確認できた範囲 |
| --- | --- |
| WordPress 起動 | `wp-settings.php`、新規インストール、同じ DB に対する別インスタンスからの読み取り。CGI までの検証 |
| フック | 実 `WP_Hook` と固定オーバーレイ経由で、選定した1つのフィルターの順序・値・終了後の状態を比較 |
| 異常終了 | 固定 PHP 8.5.12 の Windows／Ubuntu で、要求書き込み前と `begin` の通信失敗時に、参照ハンドルおよびストリームの解放を確認 |
| ホスト試験 | Rust 1.94.0 の locked／offline ビルドと39件の試験が、同じ160入力で Windows／Ubuntu とも成功 |
| 移植台帳 | 継承分の79 API・2コンポーネントを追跡。全 API の棚卸しと製品受入は継続中 |

| 工程 | 確認結果と残件 |
| --- | --- |
| 現行差分の回帰 | Windows の `recastpress-wp`・`recastpress-db` は511件成功、隔離 DB を使うため通常実行で除外した1件は MySQL 8.4.13・MariaDB 11.8.9 の両方で各62項目を確認した。フックの解放応答2件とネイティブ PHP の継続・例外・再入の比較も成功した。[MySQL](../compatibility/evidence/database-mysql.json) · [MariaDB](../compatibility/evidence/database-mariadb.json) |
| 固定 DB での起動 | Docker レジストリで両イメージの取得が停止した。Ubuntu の隔離したローカルプロセスでは、公式署名を照合した MySQL 8.4.13 と MariaDB 11.8.9 の両方で、実 PHP-WASIX の install/read が CGI 200 を返した。フック観測の一致、12テーブル、DB 切断・正常停止と160入力の再照合を確認した。[MySQL](../experiments/php-wasix-wp-bootstrap-probe/evidence/linux-local-wp-boot-mysql-2026-11-25.json) · [MariaDB](../experiments/php-wasix-wp-bootstrap-probe/evidence/linux-local-wp-boot-mariadb-2026-11-25.json) · [再実行手順](demo-full-wp-bootstrap-hook.ja.md) |
| 常駐 HTTP | PHP 互換境界の検証器をファイルパスから読み込めるよう修正した。既存の HTTP アダプター14件とコントローラー16件が成功した。通常 PHP のホーム・404・反復404は両 DB で再現した。Windows の MariaDB はサンドボックス内で最初の DB 同一性確認がタイムアウトし、サンドボックス外の隔離 DB で再試行して回収まで確認した。Linux のフック試験では1回だけコンパイルし、16個の新しい PHP ゲストで参照、コールバックの変更、例外と再入を実行した。通常 PHP との比較14件と、最後に再実行したフィルターの一致を確認した。現行オーバーレイを通る実ソケットのホーム・404比較と、常駐ワーカーの受入が残る。[コンパイル再利用の証跡](../experiments/php-wasix-wp-hook-dispatch-probe/evidence/linux-compile-once-2026-11-25.json) |
| Rust Query | 最新の投稿を表示する単一サイト設定で、ホーム・記事ID・固定ページID・検索・明示的な404の初期フラグとページ送りを実装した。固定 WordPress 7.1.3の `WP_Query::parse_query` と照合した。SQL、公開状態の変更・再入、Loop、テンプレート選択への接続が残る。[実装](../crates/recastpress-wp/src/query.rs) · [比較ケース](../crates/recastpress-wp/tests/public_query_contract.rs) |

既存の常駐 HTTP アダプターは v0.5 のワーカーの241個のソースを固定している。現行の入力は256個で、既存の入力のうち19個のハッシュが異なる。v0.6 用ワーカーと対応するビルド証跡を用意し、実ソケットの比較を行う。[既存 HTTP アダプター](../experiments/php-wasix-wp-session-http-probe/src/main.rs)

固定 PHP-WASIX と WordPress を準備済みの Linux では、次のコマンドでコンパイル済みモジュールを再利用する。コールバックの指紋は各ゲスト内で照合し、最初と最後のフィルターの値・順序・終了状態を比較する。

```sh
cargo +1.94.0 run --locked --offline \
  --manifest-path experiments/php-wasix-wp-hook-dispatch-probe/Cargo.toml \
  -- --batch filter action-throwable action-nested filter
```
