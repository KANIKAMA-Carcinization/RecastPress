# RecastPress v0.6 改訂設計

作成日：2026-11-10（日本時間）
設計版：**v0.6**
状態：ユーザー指定による改訂設計。実装・受入はこれから行う。
基点：`dev/v0.5` の `b3c819b`。設計作業ブランチ：`design/v0.6`。

**WordPressの要求解釈、Query、保存、権限、標準コンテンツ処理をRustコアへ移す。PHP-Wasmは既存テーマ・プラグインを実行し、PHPの値・参照・オブジェクトとWP互換APIを提供する層とする。** RustがWP固有の判断と状態遷移を担い、PHP拡張を必要な位置で呼ぶ製品へ改訂する。

[WPコアのRust移植とPHP互換界面の検討](../2026-11-09-wp-core-rust-boundary.ja.md)の推奨C案を、本版の設計方針として具体化した。v0.5のHTTP・PHP実行・DB・キャッシュ・変更追跡・比較基盤を統合し、元WP全体を起動する経路は比較基準と移行中の明示的な委譲に使う。

## 2 到達点と互換性

### 2.1 移すものと残すもの

| 領域 | v0.6の到達点 |
| --- | --- |
| WPコアの意味 | bootstrap順序、rewrite、Query、Loop、保存、認証・認可、標準REST、cron、標準描画等をRustで実装 |
| PHP互換表面 | 元の関数名・class・method・引数・公開property・globals・参照・継承を、対象版の契約に合わせて提供 |
| 拡張 | 既存PHPテーマ・プラグイン・独自callbackを同じ要求内PHP環境で実行。利用者によるRust移植を前提にしない |
| PHP言語 | zval、object identity、参照、closure、PHP例外、clone・serializer等の言語操作をPHPに保持 |
| 残存する標準PHP処理 | 分野ごとに一時委譲として登録し、Rustへの置換と元実装の退役条件を必ず持つ |
| 比較用WP | 固定した元WPを通常PHPと既存PHP-Wasmで実行。製品の暗黙の代替コアにしない |

「WPコア移植完了」は、対象機能の標準の判断・処理本体をRustへ移し、元PHPアルゴリズムを使わずに比較を通ることとする。関数wrapperやSQL実行だけのRust化を、その業務分野の移植完了には数えない。

互換宣言のPHPファイル、PHPランタイム、第三者拡張や同梱外部ライブラリまで除去することは別の指標とする。標準block・管理viewの実装本体がPHPへ残る間は、その標準処理は未移植と表示する。未移植コードを「互換界面」へ分類し直して完了にしない。

### 2.2 機能の母集団

初回の製品受入は単一サイトを対象とし、公開閲覧、投稿・固定ページ、分類・meta・options、ユーザー・権限、コメント、メディア、検索・feed・sitemap、標準REST・AJAX、cron、blockとclassic theme、標準管理操作、install・upgradeを分野別に追跡する。認証済み操作を後から別コアとして付け足さない。

マルチサイト、XML-RPC、特殊なPHP extensionやOS能力など、初回profileで未提供の項目は母集団と残件へ記録する。単一サイトprofileの完了を、対象版の全WP機能の完了とは呼ばない。全APIの列挙と、実要求の標準経路を退役させる作業を並行して進める。

### 2.3 互換性の優先範囲

公開APIの意味に加え、通常の拡張が使う公開property、globals、同一object、参照、継承・overrideを必須の設計対象にする。method経由の変更だけへ互換範囲を縮めない。ソース本文・元の行番号・private実装位置までの一致は個別差分として管理する。

固定比較基準は、保存済みのWP 7.1.3、PHP 8.5.12、MySQL 8.4.13／MariaDB 11.8.9とする。これは既存証跡を接続する基準であり、最新推奨版・将来の出荷版を宣言するものではない。出荷する組合せは再固定し、その版の比較と保守条件を満たす。

## 3 v0.5からの改訂

| 論点 | v0.5 | v0.6 |
| --- | --- | --- |
| WP要求の主導権 | PHP版WPが要求を処理しRustが基盤を所有 | Rustコアが標準処理を進め、必要なPHP拡張を呼ぶ |
| bootstrap | 元の `wp-settings.php` を実行 | Rustが段階を管理し、互換loaderが宣言と拡張を読み込む |
| Query・保存 | SQL構築・業務順序は主にPHP | SQL構築・状態遷移・標準hook位置をRustへ移す |
| PHP境界 | DB・cacheの有限RPCが中心 | 要求内handle、公開状態同期、入れ子の継続・callbackを追加 |
| 認証 | PHP標準判断への接続と既存Rust部品が併存 | 標準判断を一つのRustコアへ集約し、拡張の変更点を保持 |
| 進捗 | 実行基盤と有限比較の成果 | 分野別の意味の移植、元実装の退役、委譲回数も測る |
| 最初の中核成果 | 元WPのhome／404 | PHP拡張が直接変更・再入するRust版Query、Loop、template選択 |

## 4 設計判断

以下は本改訂で採る設計上の選択である。成立性の確認や製品の数値条件が残るものも、選択した構成と試験の出口を明確にする。

| ID | 判断 |
| --- | --- |
| V06-D01 | 業務コアをRustへ移す推奨C案を採用。基盤だけのRust化を最終形にしない |
| V06-D02 | PHP-Wasmによる既存拡張の実行を維持。公開要求からも必要なPHPを実行する |
| V06-D03 | 公開状態のPHP実体を観測上の正本とし、Rustは必要なsnapshotを境界ごとに取り直す |
| V06-D04 | 初期接続はPHP dispatcherとRust状態機械の継続方式。実行中Wasmへのhostからの直接再入を必須にしない |
| V06-D05 | 初期transportは既存privateチャネルを拡張。意味の契約を固定し、binary化・Zend bridgeは測定後の実装選択とする |
| V06-D06 | 移植済み分野の元PHPアルゴリズムをloaderから外す。未移植分は開始前に選ぶ明示委譲として管理 |
| V06-D07 | hooksの発火と反復・変更規則をRustへ移す。PHPはcallable、参照、公開callbacksを表現 |
| V06-D08 | Queryとoptionsから縦断し、保存・認証・標準機能へ拡張。文字列APIの件数増加を主工程にしない |
| V06-D09 | DB・cache・CDCのPoCを再利用し、正しさと総費用を別に確認。最適化失敗時もRustコアから正本DBへ進む |
| V06-D10 | 設計版と実装版・試験済み状態を区別。v0.6作成だけで既存PoCや製品を0.6.0受入済みにしない |

### 4.1 継承する製品条件

WP互換DBと管理ファイルを正本とする。一体化した専用サーバーとして、安全で予測可能な運用、互換性と利用者負担の軽減、性能・資源最適化を評価する。Rustコア移植そのものも本プロジェクトの中心目的とし、性能改善率だけで移植範囲を周辺へ戻さない。

v0.5で定めた次の条件は維持する。

- Node.jsを製品の実行依存にせず、RustがPHP-Wasmを直接実行する。
- 同一要求の受入済み拡張はPHP環境を共有し、サイト・役割・workerで隔離する。
- 標準wpdb APIを互換対象とし、mysqli handle・driver内部への直接依存や本体接続の迂回を拒否する。
- 公開GETを含め通常処理のDB書込みを許す。標準操作の認可はRustへ移し、拡張固有操作の検査はその拡張が担う。
- 動的応答は有限サイズで完成・検査後に送信する。即時ストリーミング必須の機能は初回非対応。
- 応答cacheは初期設定on、TTLなし、変更時全パージ、容量は完全自動。実利用は整合性・適格性・資源が成立する場合だけ許す。
- cache可否だけ不明なら通常動的実行へ進む。具体的な基盤衝突の疑いは保留・開発者への報告、既知の複合衝突は拡張全体を拒否する。
- 本体、互換定義、同梱WP対応資産、PHP-Wasm、host、接続層を検証済みリリースとして一体更新する。
- 移行の転送／file取込み、標準管理画面と独自機能1画面、OIDCの3モード・初期off・連携専用の一度限り許可、MFA非実装、三環境の配備目標を維持する。

旧v0.45の「公開起点でPHPを動かさない」「利用者がPHPテーマをRustへ移す」は本構成へ復活させない。v0.5の「WPの業務判断をPHPへ残す」「全API移植を主工程にしない」は、前者を置換し、後者を縦断移植優先という意味へ改訂する。旧要求番号を上書きせず、本版の条件を次節のIDで追う。

## 6 版と今回の変更範囲

本版は設計v0.6であり、次の実装系列の開始版を **0.6.0** とする。今回の成果物は文書のみ。現在のCargo workspaceは0.5.0のままとし、0.6実装へ切り替える最初の変更でCargo・lock・CLI表示・release manifestを一括更新する。設計文書の更新を実装済みの版へ読み替えない。

v0.5・v0.45の設計と保存済み証跡は履歴として維持する。新設計との相違は本書と[成果の統合と追跡](evidence-and-traceability.ja.md)を優先する。本改訂でコード、依存、DB、既存試験結果を変更せず、実装時は段階ごとに検証して切り替える。
