# v0.5 DB実測結果

2026-11-09時点の記録。WordPress 7.1.3、MySQL 8.4.13、MariaDB 11.8.9を使った固定試験をまとめる。LinuxのPHP-Wasm試験とWindowsの通常PHP・ネイティブRust試験は、それぞれ環境を明記する。リンク先には試験条件、入力と結果の照合、失敗時の記録を残している。

## wpdbとRustのDB接続

- PHP-WasmからRustが所有するDB接続を使い、標準wpdbの固定27ケースと更新ヘルパー15ケースを両DBで通常PHPの基準と照合した。更新ヘルパーの試験は40 RPCを通過した。対象は固定した入力とAPIである。[wpdb試験](../experiments/php-wasix-wpdb-probe/README.ja.md)
- 有効UTF-8の固定データでは、日本語、絵文字、アクセントの異なる表現を含む31観測・22 SQLを両DBで照合した。PHP-WasmとRust DBを通す試験でも52 RPCが基準と一致した。[UTF-8試験](../experiments/php-wasix-wpdb-utf8-probe/README.ja.md)
- 実DBのエラー本文をwire、RustのDB actor、PHP-Wasm上の標準wpdbで比較した。UTF-8の `c3a9`、非UTF-8の `e9`、後続のエラーと成功時の状態消去を固定7 SQL・13 RPCで両DBについて確認した。[raw ERR試験](../experiments/php-wasix-wpdb-raw-error-probe/README.ja.md)
- Rust所有のDB接続を使い、元のWordPress installer、通常の `wp-settings.php` 起動、別の新規要求での読み取りを両DBで実行した。固定された公開19項目が通常PHPの基準と一致した。[通常WP起動試験](../experiments/php-wasix-wp-bootstrap-probe/README.ja.md)

## DB更新と共有キャッシュ

- Windowsの両DBで固定1行を使い、ROLLBACK時のキャッシュ維持、COMMIT観測後の失効、監視が切れた後のDB直読を確認した。同じDBの保持済みログ位置から再生した後は、新しい世代を使い、古いチケットによる格納を拒否した。[共有キャッシュと復旧](../experiments/binlog-shared-cache-probe/README.ja.md)
- LinuxのPHP-Wasmでは、標準WordPressが発行するautoload SELECTの117行・2列を保持し、準備済みの404を2回処理した。対象SQLは1回実行し、2回目は共有ヒットした。この試験では所有DBの読み取りロックで対象を固定した。[autoload共有試験](../experiments/php-wasix-autoload-cache-probe/README.ja.md)
- 続く両DBの試験では、実際の `rp_options` に固定autoload行を追加し、別接続から更新した。3件の404で対象SQLを2回実行し、共有ヒット1回とコミット観測による失効1回を確認した。更新後は対象SELECTの結果が変わり、ほかの比較対象RPCと通常PHPのページ応答は一致した。[コミット失効試験](../experiments/php-wasix-autoload-binlog-probe/README.ja.md)
- 同じログの位置が進み、共有結果を利用できない場合は、両DBで共有結果の予約を解放して標準SELECTを直接実行し、更新後の値を取得した。[位置不一致時のDB直読](../experiments/php-wasix-autoload-bypass-probe/README.ja.md)
- Windowsの固定テーブルによるライブbinlog試験では、読み取り4回に対し位置を4回確認した。共有ヒット、監視の適用待ちでのDB直読、コミット適用後のヒット、監視切断後のDB直読を両DBで確認した。[ライブ監視試験](../experiments/binlog-autoload-frontier-probe/README.ja.md)
- 監視接続と読み取り接続が同じ所有DBを参照することを、別アカウント・別接続の識別値で確認した。異なる識別値は共有許可を得られず、読み取り接続による監視用nonceの参照はDB権限で拒否された。LinuxのPHP-Wasmでも、404の3要求それぞれが実際に使うDB接続を監視接続と照合した。[ネイティブの接続同一性](../experiments/binlog-source-identity-probe/README.ja.md)・[PHP-Wasmの接続同一性](../experiments/php-wasix-autoload-bypass-probe/README.ja.md)
- Linux CIのsource `e2758d4` では、PHP-Wasmのautoload SELECTの直前に、要求が観測した位置とライブ監視の適用位置を照合した。更新後、監視の適用を保留した要求はDBから直接読み、その後に同じbinlog接続で行とコミットを検証した。両DBのCIが成功した。[MySQL証跡](../experiments/php-wasix-autoload-bypass-probe/evidence/ci-42538760772-mysql/provenance.json)・[MariaDB証跡](../experiments/php-wasix-autoload-bypass-probe/evidence/ci-42538760772-mariadb/provenance.json)

## 現在の確認範囲

上記の成功は、それぞれに記載した固定入力、所有DB、指定バージョンの結果である。wpdb全API、任意のSQL・文字コード・collation、任意プラグイン、並行更新中の安全な再格納、binlogローテーション後の復旧、ログ消失後の再同期は引き続き検証対象である。共有キャッシュの試験では、対象SELECTの削減に加え、監視用SQLを含むDB負荷と応答時間の比較が必要である。[実装計画](v0.5-wp-bootstrap-plan.ja.md)
