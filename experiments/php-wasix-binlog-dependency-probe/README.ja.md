# PHP-Wasm要求間で実binlogのコミットを観測する

1つのRustセッションで、通常WordPressのPHP-Wasm要求を3件実行する。固定行を読む非公開コマンドは既存の共有読取りを再利用する。初回は旧値をSQLから取得し、2回目は同じ値にヒットする。コントローラーは3回目の前に別接続から1行を更新し、コミット後の値を独立したSQL接続から確認する。

Rustは専用の監視アカウントで、保持した開始座標から同じbinlogファイルの更新を有限に再生する。CRC、行の前後像、XID、位置、EOFを照合した後にだけ共有キャッシュを失効させる。3回目は更新後の値をSQLから取得し、ホーム応答と標準オブジェクトキャッシュを維持する。所有DBの専用スキーマに範囲を限定し、WordPress用アカウントには固定行の読み取り権限を付与する。

この試験は要求間の制御下でのコミット観測を対象とする。継続監視の遅延、切断中の再開、ローテーションや任意のWordPressキーへの接続は別の範囲として扱う。

source `190cc83` のLinux CIはMySQLとMariaDBの両方で通過した。各DBでコンパイル1回・新規要求3件を実行し、依存SQL 2回、共有ヒット1回、コミットによる失効1回を確認した。binlogは更新行1件、コミット1件を含む7イベントで、EOFとソース再確認まで通過した。3要求のホーム応答とコンテキストは通常PHPと一致し、所有DBも正常終了した。68テスト、入力262件と生成5件を照合した。[MySQL証跡](evidence/ci-42508028753-mysql/provenance.json)・[MariaDB証跡](evidence/ci-42508028753-mariadb/provenance.json)
