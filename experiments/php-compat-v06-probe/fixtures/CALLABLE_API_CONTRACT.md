# callable_api wire contract v2

Baseline c5c414e; envelope stays version1/request surface-probe-1. Root start is exactly {operation:callable_api,protocol:2,request_generation:'71'}. Registry generation71. Existing root run_script/close_registry/request_finished and callback/release ownership rules remain, with the differences below. Uncaught script typed abort remains future, not a successful result.

## Rationale and ownership

Rust owns the WordPress API algorithm, bindings, counters, public hook stack and priority iterations. PHP owns actual values, identity and primitive language operations. A normalization probe followed by replayed warning text is forbidden: an actual PHP warning handler may call Core, throw, or mutate the hook while the API is in progress. Rust requests the same primitive access phases as pinned plugin.php/WP_Hook; PHP emits genuine conversion warnings/errors at those phases.

API wrappers retain raw by-value parameter values in fresh request-local `argument` slots, without key coercion, callback-ID construction or integer casts. The argument slot preserves actual PHP arrays/objects for native invalid-offset errors. Scalars are not eagerly normalized. Filter value/extra args still use the existing POD domain; broad heap-valued filters/resources are separate integration work. Supported successful hook/priority originals are null/bool/int/float/bytes. Invalid array/object hook/priority inputs must yield their actual native TypeError at the correct phase. Resources remain explicitly outside this successful scalar profile, not silently converted to null.

Handle descriptor has the existing five fields, request71, kinds argument/callable/throwable. Argument retain is fresh, no identity dedupe or is_callable test. PHP wrapper parameters remain alive while Rust finishes each API, so argument-slot release precedes the actual wrapper parameter drops. Mirror argument registration is confirmed, and exact tuples retire only after release ACK.

## Exact CallCore payloads

Every API child uses its currently active PHP effect as parent as before. `arguments` is an exact-name map of argument descriptors. All listed arguments are retained even when their later use is skipped; retained PHP values are not inspected during transport.

- add_filter: {api,arguments:{hook,callback,priority,accepted_args}}
- remove_filter: {api,arguments:{hook,callback,priority}}
- has_filter: {api,arguments:{hook,callback,priority}}
- apply_filters: {api,arguments:{hook},value:<POD>,args:<extra POD[]>}
- current_filter: {api}; no argument handles.
- doing_filter: {api,arguments:{hook},any:<hook === null>}; explicit null/default is any, all other types compare strictly without key coercion.
- did_filter: {api,arguments:{hook}}

Return remains {api,completion}; Value result is POD. has_filter search may now return int OR byte-string priority, or false; exact-int and any modes return bool. current_filter returns the actual original scalar or false when empty (a running false hook is separately observable through doing_filter()). did_filter returns null or a nonnegative POD int; null is retained when a reentrant key-conversion warning invalidates the counter read operand.

Every owned argument is released by a final boundary release_arguments effect before this API Return, including on the API's PHP Throwable outcome. No caller-supplied expected results or PHP-maintained shadow dispatcher.

## Boundary InvokePhp

Exact payload {operation:'boundary',effect_id,action,arguments:<action-specific object>}, caller effect is parent. Resume is {effect_id,completion}; Value completion contains ordinary JSON below, NOT a POD wrapper, except accepted_args explicitly returns a POD node. PHP Throwable completion remains {kind:'php_throwable',handle,class_hex,message_hex} and rethrows the same object on API Return. User warning handler CallCore is nested under this boundary effect.

Actions:

- array_key: arguments {handle:<argument>,access:<isset|nested_isset|read|write|unset|increment>,null_to_zero:<bool>}. Execute ONE requested PHP primitive offset access, with no extra externally visible conversion. `nested_isset` executes a two-level `isset($dummy[$original]['callback'])` after seeding the dummy inner entry with the normalized outer key; it is used only for remove-filter priority existence, whose pinned WP expression has two offsets. For priority null_to_zero=true only null becomes int0 before access; returned original is that effective int0. For hook false. Value is {original:<scalar POD>,key:<canonical int|string key {type,hex}>}. The helper must preserve actual warning severity/message/order and TypeError context. If read/unset needs an additional state-sensitive undefined-offset warning, Rust requests it separately after observing post-handler Core state; do not fabricate warning text.
- missing_offset: arguments {key:<normalized Key>}. Read that key from an empty PHP array, generating the genuine undefined-offset warning. Value {missing:true}. The key is already canonical, so no extra key-conversion warning.
- null_property: arguments {property:'callbacks'}. Read that property on PHP null, generating the real native warning; Value {missing:true}.
- null_foreach: arguments {}. Execute `foreach` over PHP null, generating the genuine native warning; Value {missing:true}.
- null_method: arguments {method:<add_filter|remove_filter|has_filter|apply_filters>}. Call that method on PHP null and return its actual Error as Throwable completion; it cannot produce a Value.
- callback_id: arguments {handle:<callback argument>}. Use the pinned helper with ignored hook/priority parameters null/false; callback ID/key rules are unchanged. Value {key:<normalized callback Key or null>}.
- accepted_args: arguments {handle:<argument>}. Perform actual PHP `(int)` cast now, retaining any genuine warning/Throwable; Value is canonical POD int.
- retain_callable: arguments {handle:<callback argument>}. Retain the actual current PHP value by value without is_callable; Value {handle:<fresh callable descriptor>}.
- hook_scalar: arguments {handle:<argument>}. No array-key conversion. Value {supported:true,value:<scalar POD>} for null/bool/int/float/string, or {supported:false,value:null} for other PHP types. For doing_filter, a non-scalar cannot strictly equal any successfully entered scalar hook.
- release_arguments: arguments {handles:<all this API's argument descriptors, each once>}. One batch effect; release each exact slot, allowing reentry under this effect. Value {released:true}. Mark all old exact tuples release-pending before effect, allow newly allocated slot generations, unregister only confirmed old tuples after ACK.

The action vocabulary can be extended only after recording the exact WP access/assignment phase needed; field sets are closed. In particular nested priority assignment and undefined-offset primitives need explicit action(s) if a single array_key access does not reproduce the measured PHP VM warning order. Do not collapse those phases or invent warning counts.

## Typed values delivered to Rust

HookArgument { original:HookScalar, array_key:PhpKey } comes from an array_key result. PHP-normalized key indexes bindings and counters; original scalar stays on the Rust public stack and in all listener arg0. Doing membership uses PHP strict scalar equality (NaN never equal; +/-0 equal). Literal normalized bytes 'all' selects the reserved all binding.

HookPriority { original:HookScalar, key:PhpKey } likewise preserves post-null-normalization ORIGINAL priority, not just its array key. Bucket/current-priority identity is key. WP add passes original into resort's `new_priority === current_priority` check; e.g. raw '7' is not identical to an int7 bucket even though it indexes it. Null alone is effective original int0. ksort uses stable SORT_NUMERIC; resort's min and `<` are PHP regular comparisons and strict identity remains distinct.

Existing Rust &str/i64 APIs remain adapters. Typed entrypoints must own this state in Dispatcher/Storage; no peer shadow stack. An opaque HookTarget pins a selected WP_Hook-equivalent storage object across PHP boundary effects, so handler removal/rebinding cannot retarget the outer method. Empty registered hook-object existence is distinct from has_callbacks.

## Callback and summary fields

Callable InvokePhp is now exactly {operation:'callable',effect_id,handle,hook:<original scalar POD>,priority:<normalized priority Key>,call_mode,args:<POD[]>}. Engine supplies original scalar in all arg0; peer does not reconstruct it from a binding string. Named accepted_args slicing and zero mode remain unchanged. `release_callable` retains its existing one-handle release behavior. The new `release_callable_unwind` effect is exactly {operation,effect_id,handle,throwable}, with both descriptors validated before release. PHP throws the supplied Throwable in a `try` and performs a required final registry release in `finally`. If release completes normally, PHP resumes with Value {released:true}, leaving the pending Throwable in Rust. If a destructor throws, PHP resumes with that actual Throwable descriptor; Rust replaces its pending Throwable with it. PHP does not synthesize an exception chain. The four pinned cases record the actual chain and assert that their plain destructor Throwable B has A as its immediate previous object.

Peer result adds exactly `boundary_effects` and `argument_release_effects` to the previous result fields. boundary_effects counts non-release boundary effects; argument_release_effects counts release_arguments batches. api_counts still exactly seven API names, actual Rust observations. release_effects counts callable lease releases, including unwind releases. For successful primary run:
B = sum(api_counts)+callback_invocations+release_effects+boundary_effects+argument_release_effects.
frames_from_php=B+4; frames_from_rust=B+3.
Root script program observation is ordinary JSON, independently compared against pinned native WP and actual PHP-Wasm. It includes warning severity/message hex and order measured by a shared error handler, not guessed Rust state or future completion flags.

## Action heap positional arguments

For do_action, CallCore.args is an ordered list of {type:'handle',handle:<argument descriptor>} markers, one for every positional value, including scalars. Each positional handle is fresh for that API call and joins the same exact release_arguments batch as the named API arguments; when there are no positional values, args is an empty list. For an all callback, InvokePhp.args is the hook-name POD followed by one handle marker for each positional value. A named callback receives only its accepted positional slice, represented by the same markers. The adapter resolves markers to retained PHP values before call_user_func_array.

The heap_argument_continuation action observation uses a PHP object and an array containing a reference to a scalar cell. It records only JSON-safe class names, strict object identity booleans, property strings, and cell values. The named callback mutates both values, dispatches a nested action with them, and records the outer callback's resumed view. The pinned contract checks identity and reference-cell visibility without adding a value codec.

## Confirmed algorithm phase map (pinned PHP 8.5.12 / WP 7.1.3)

For hook-binding bucket operations, Rust captures the current hook-table operand/version before asking PHP to perform key coercion. The real PHP access may invoke a user handler that reenters and mutates the global hook table using copy-on-write. After that handler returns, resolve against the captured version only while it still has owners beyond the transient operation operand; if that operand is the version’s only remaining owner, release it and treat the fetch operand as null. Drain releases and any destructor reentry from dropping an old version before the next lookup or native error. This follows the pinned runtime’s `slow_index_convert` behavior in [php-src 8.5.12 `Zend/zend_execute.c`](https://github.com/php/php-src/blob/php-8.5.12/Zend/zend_execute.c).

A retained array operand whose requested key is absent is distinct from a null operand. Request `missing_offset` only when the source operation reads a genuinely absent key from a live array. If COW leaves the operation with a null operand, perform the corresponding direct `null_method` call; do not add an undefined-key warning. `increment` performs one real PHP compound ++ offset on a preinitialized dummy value, returning only key/original; real count stays in Rust.

The `counter_cow` group measures the filter counter array separately from hook bindings. For an existing float-key counter, a nested string-hook apply during the outer `isset` or compound `++` warning leaves the counter at 1 (the read-only control reaches 2); a nested write during the later hook lookup leaves the increment committed at 2. For a missing float-key counter, a nested write during the counter assignment leaves `did_filter` at 0 while the outer apply still returns its input; writes during the earlier `isset` or later hook lookup leave the count at 1. For `did_filter`, a nested write during its `isset` returns 0; during its counter read it returns actual null, with no undefined-key warning. The additional `nested_read_owners.inner_increment` phase holds outer and middle `did_filter(float)` reads while a same-key inner apply reaches `++`. Its float apply returns `seed:middle`; the middle read remains 1 and the outer read becomes null. A read-only inner handler leaves the final count at 2; a nested string-hook write leaves it at 1, while the nested string apply returns `inner`. These results cover only the 18 named cases; they do not generalize to other array operations.

- add_filter outer: hook isset -> check binding object existence (empty object counts). If missing, hook write -> bind a NEW empty object (replace any binding that the warning handler created during this write, release orphan leases through effects). Then hook read -> resolve using that access's captured operand/version and pin the resulting receiver. If a retained array has a genuinely missing key, request missing_offset then null_method(add_filter). If the operand is null after handler mutation, call null_method(add_filter) directly, without missing_offset. Both errors precede callback-ID/priority processing.
- add_filter inner: callback_id; if null return true without priority/cast/retain. Priority isset(null=>0) captures `priority_existed`; then accepted_args is cast and the actual callback entry is assigned. With a float priority and object accepted_args, the pinned engine warning order is line101 (`isset`), line105 (`(int)`), then line103 (the nested write key). Warning handlers may mutate the same bucket between these steps. Preserve the pre-warning `priority_existed` decision for sorting/resort, and hold/release the callback-table operand according to each actual PHP primitive boundary. In the measured line105 reentry case, nested add/remove completes before the outer callback entry is assigned; a handler that removes the whole current bucket can still be followed by the outer assignment, while a line103 handler removing the bucket leaves the outer callback absent. Do not generalize this to unmeasured callback-bucket operations.
- has_filter: hook isset -> if absent false. Hook read -> resolve through its pre-coercion table operand/version and pin the current receiver. A live array with a missing bucket uses the source missing-offset path before null_method(has_filter); a null operand calls null_method(has_filter) directly. Callback=false(any) returns target.has_callbacks. Otherwise callback_id; falsey/null ID =>false. Only original int priority uses exact-key boolean lookup; other third-argument types are ignored and scan priorities, returning actual int/string key or false.
- remove_filter outer: hook isset -> if absent false. Hook read -> resolve through its pre-coercion table operand/version and pin the receiver before inner processing; distinguish a live missing bucket (source missing-offset then null-method path) from a null operand (direct null_method(remove_filter)). Inner callback_id null =>false and skip priority. Valid ID: priority nested_isset -> snapshot exact callback presence on the pinned target; if present priority unset -> remove callback entry and yield final releases. Then priority read -> read post-handler bucket. If missing, native missing_offset gives null. If empty/null, priority unset -> FORCE remove the bucket selected by the earlier empty decision even if handler registered entries during the unset warning; yield final leases before refreshing priorities/resort. Retire receiver pin before outer's global callbacks read. Outer hook read resolves against the table operand captured before that read's key coercion and inspects the current global binding callbacks (not the old receiver). A live missing bucket follows missing_offset + null_property(callbacks); a null operand uses the native null-property path directly. Empty/null -> hook unset -> unbind the current object, then yield orphan releases. A new binding created by a destructor AFTER unbind must remain.
- did_filter: hook isset -> if no counter return0; otherwise hook read -> return the actual current counter operand, including null when nested COW invalidates the suspended read. The finite warning-handler outcomes below distinguish both phases.
- doing_filter: hook_scalar only, no key conversion; null(any) is strict special sentinel. Non-scalar cannot equal the supported scalar stack. Current_filter reads typed original stack directly, no PHP effects/args.
- apply_filters: hook isset on counter -> if missing hook write then set count1, else hook increment then increment latest count. Then inspect literal all object; if present push original hook and run all. If that object has no callbacks, reproduce the pinned do-while by issuing missing_offset(key:int0) then null_foreach; these warnings are part of the source behavior. For the named hook lookup, capture the hook-table operand/version before its key-coercion effect and resolve against that retained version or a null operand using the rule above. Preserve existing WordPress all-removal/pop rules. If present and no current all binding, push original hook. Then perform the named receiver read on the resolved operand; a genuinely absent key uses only the source-required missing-offset path, while a null operand goes directly to null_method(apply_filters). Run named filter on captured object, release abandoned foreach locals/snapshots before forwarding Throwable, and pop only at the original normal-completion phase. Counter and stack belong in core Dispatcher, not a peer shadow.

Lower-level missing-offset/null-property effects are requested only when the resolved live array operand has the missing key and the source operation performs that read. Warning handlers may themselves reenter; a null operand is not reread as an array and never receives a fabricated undefined-key warning. The hook-binding-table COW rule above, the finite counter-map cases below, and the 18 priority-bucket observations below apply only to their measured operations; they do not claim general PHP array COW behavior.

## Implemented fixture scope and limits

This contract describes the isolated PHP fixture only. The fixture exposes the pinned WordPress signatures/defaults for `_wp_filter_build_unique_id`, `add_filter`, `remove_filter`, `has_filter`, `apply_filters`, `current_filter`, `doing_filter`, and `did_filter`. It delegates hook state, ordering, counters, stack state, snapshots, and registration leases to the Rust peer through the operations above. The fixture has not connected the production WordPress dispatcher, plugin bootstrap, hooks, or query path; it does not establish whole WordPress compatibility.

The shared program contains 20 original observations, 20 coercion observations, 18 counter COW observations, 18 priority-bucket COW observations, 8 remove-filter COW observations, and 3 hook-unset reentry observations (87 leaves total). `counter_cow` covers `existing_counter` phases `counter_isset`, `increment`, and `later_hook_lookup`; `missing_counter` phases `counter_isset`, `counter_write`, and `later_hook_lookup`; `did_filter` phases `counter_isset` and `counter_read`; and `nested_read_owners` phase `inner_increment`. Each counter phase has a read-only control and a single nested string-hook write. The nested-owner phase records the actual middle float apply and nested string apply results, along with both suspended `did_filter` results.

`priority_cow.float_priority` has a control and four active-iteration mutations: add at the first float-key warning (`isset`), remove the full priority-7 bucket at that warning, add at the later write warning, and remove the full bucket at that write warning. The first active foreach keeps its captured callbacks; a line101 handler that removes the bucket can still be followed by outer callback registration, with the next apply ordered `anchor, outer`, while removal at line103 leaves only the anchor. `accepted_args_partial_bucket` records the read-only and active add/remove-victim cases for an object-to-int accepted_args warning; the removed victim remains in the current foreach snapshot, and the next apply sees `seed, nested, outer, anchor`.

`accepted_args_reentry` measures object listener lifetime during a line105 warning with a whole-bucket removal, both with and without priority-7 recreation. In these cases, old listener destructors run after the handler mutation while the current apply still completes its saved iteration; the next apply visits the new live bucket. `float_accepted_args_lifetime` performs no apply/foreach while the warning handler removes the last registered seed alias. With float priority and object accepted_args, the actual warning order is line101, line105, line103: the seed destructor runs after handler exit for line101, during the handler for line105, and after handler exit for line103; outer is absent when removed at line103. `throwable_cleanup` adds the four control/throwing-destructor combinations for `isset` at warning1 and bucket write at warning2. The handler removes the seed, clears its last alias, then throws A. Normal destruction preserves A; a throwing destructor replaces it with B whose native `getPrevious()` is the same A object. These 18 cases are finite observations, not a claim about arbitrary callback-bucket mutations. All priority observations are captured from the original pinned WordPress `plugin.php`/`WP_Hook` and are intended to be matched by the adapter.


remove_cow.priority_first measures five public remove_filter cases around the priority-key isset and subsequent bucket changes: control, nested removal, insertion into a missing callback ID, an emptied priority bucket, and remove/recreate. priority_read_unset adds a separate control plus handlers that add priority 7 during the post-remove read and unset. The exact remove_filter result, replacement visibility, warnings and apply trace are pinned; the read warning removes a replacement added by its handler, while a replacement added at unset remains and runs before the anchor.

hook_unset_reentry pins three public-API cases for the outer hook-table unset in remove_filter: control, a warning-handler add_filter(7, ...), and the same mutation while a real Throwable A is pending in finally. The nested add returns true, then the outer unset removes that replacement from the live binding. In the pending-Throwable case, release of the replacement object throws B; PHP returns the same B object with B.getPrevious() === A. The shared observation records warning/event order and identity checks without source-line numbers. These observations are finite and do not generalize to arbitrary PHP array COW or all target-unset interleavings.
The measured scope also includes callable identity forms, delayed invalid-callable failure, lifecycle/reentrancy, typed hook keys, warning/error ordering at exercised coercion phases, strict `doing_filter()` behavior, stable numeric priority ordering, typed `has_filter()` results, and active priority insertion. Its numeric priority comparison matrix has 24 two-entry registration orders and 18 active-add cases, including nonnumeric strings, exponent forms, large integer/string ties, and overflow forms; these are measured cases, not a claim that every PHP numeric string is covered. It includes a measured PHP 8.5.12 runtime width of 8 bytes with `PHP_INT_MIN/MAX` preserved through actual `apply_filters()` calls; the wire integer domain remains canonical signed 64-bit values.

Filter values and extra arguments use the existing materialized POD codec. Scalars, byte strings, and recursively nested arrays of those values are supported. Objects, PHP references/reference cells, resources, cycles, and reference-valued array entries are not represented by this codec and must be rejected explicitly. This restriction applies to filter values and arguments; callable slots retain actual PHP values, including closures, arrays, objects, and invalid callables, with PHP owning their identity and invocation.

The current fixture proves neither production dispatcher integration nor full WordPress acceptance. It also does not claim support for arbitrary hook objects, query APIs, broad heap-valued filter payloads, resource keys, uncaught root-script Throwable completion, or worker reuse after an abandoned request. Native/Wasm evidence is separate from the pinned PHP oracle and must satisfy the receipt/source/transcript criteria above.

## Isolated action API contract (pinned PHP 8.5.12 / WordPress 7.1.3)

The action surface is a separate `action_api` scenario with a fresh dispatcher and fresh `$wp_filter`, `$wp_actions`, `$wp_filters`, and `$wp_current_filter` state. It does not add leaves to or reorder the existing 87 filter observations. The closed action observation is recorded under its own `action_api` key and validated independently.

The seven action entrypoints are `add_action`, `remove_action`, `has_action`, `do_action`, `current_action`, `doing_action`, and `did_action`. `add_action`/`remove_action`/`has_action` retain the measured filter aliases, including a priority-zero query result of integer `0`. `do_action` always returns `null`; listener returns are discarded. `did_action` counts dispatches before callbacks run, including dispatches with no named listeners, and remains independent from `did_filter`.

The oracle checks named-hook callback argument slicing, the empty variadic call placeholder (`['']` when accepted args is positive, no callback args when accepted args is zero), and all-hook dispatch. An `all` listener receives the hook name plus every original dispatch argument regardless of whether its registered `accepted_args` is zero or one; all listeners execute before the named hook. Nested same-name and child dispatch observations include counts and current/doing-action state. A nested child Action that throws a `RuntimeException`, is caught by the parent callback as the same PHP object, and lets the parent return normally is also compared. During catch/resume the child remains current/doing; after the parent return one stale child tail is popped, leaving the parent current/doing at stack depth 1 and both counters at 1.

The action profile uses string hook names only and does not measure non-string hook-key warning order. The shared Filter fixture's broader scalar hook-key matrix does not extend this action claim; current native/Wasm action adapters evaluate a non-string key at both dispatcher lookup and the PHP counter boundary. Seeded-counter bridge cases cover int 7→8→9, float 7.5→8.5→9.5, `PHP_INT_MAX`→float 2^63→the same float, bool `true` remaining true with two `E_WARNING` diagnostics, and nonnumeric string `a`→`b`→`c` with two `E_DEPRECATED` diagnostics. In the pinned PHP 8.5.12 fixture, diagnostic severity, message, order (diagnostic→`all` listener→named callback) and counter values match fixed WordPress, native PHP, and Wasmer. The peer accepts bool, byte-string, int, and finite-float POD results; Rust Dispatcher retains its separate `u64` dispatch counter. A temporary error handler captures these diagnostics; alternate handlers and PHP versions are outside this claim.

`global_state` adds nine initial `$wp_actions` states (unset, null, false, true, int, float, string, array, and `stdClass`) crossed with two operations (`do_action` and `did_action`), for 18 fixed WordPress observations. For `do_action`, unset/null become arrays and dispatch; false converts to an array after one `E_DEPRECATED` and dispatches. True and numeric scalars throw `Error`, string throws `TypeError`, and `stdClass` throws `Error`; these failing increments leave the global value intact, invoke no callback, and leave the action stack empty. For `did_action`, the absent bucket returns int 0 for non-object states; unset creates a null global binding, while null and other scalar globals retain their type. `stdClass` throws `Error`. The Action stack is pushed only after the PHP counter boundary succeeds, so the failed increment cases have no current-action stack entry. The fixed WordPress, native, and Wasmer results match this entire 9×2 matrix, including warning/Throwable type and message, callback count, final global type/value and stack. The claim is limited to the pinned PHP 8.5.12 / WordPress 7.1.3 profile.

The separate [target-only Action counter COW receipt](../evidence/wp-action-counter-cow-poc-v1.json) compares live and by-value snapshot cases seeded with string `a`; the warning handler performs a nested dispatch of the same hook. Without a snapshot the live value ends at `b`. With a snapshot, it remains `a` during nested callbacks while the live value is `b`, then the suspended outer increment changes the snapshot-observed value to `b`. This is target-only PHP/WordPress evidence; Action COW has not been promoted to the Rust/native/Wasm bridge. The target-only COW and global-state probes are separate, source-bound receipts. None of these observations establish arbitrary PHP heap or production dispatcher compatibility.

The two throwable cuts are measured separately: the first `all` listener throws before the named hook, and the first named listener throws before its later sibling. Both increment the action count first, propagate the exact `RuntimeException`, skip remaining callbacks in that dispatch, and leave the current-action stack dirty. A follow-up dispatch increments the count again; normal completion does not repair the preexisting stack state. These are finite observations of the pinned implementation, not a general PHP exception-cleanup claim.

`wp_callable_oracle.py` runs the action case in its own PHP process, compares it to the separate native/Wasm `action_api` result, and source-binds both oracle programs. The pinned WordPress comparison covers 87 filter cases plus the 13 Action API observation groups. The latest source-bound Action bridge receipt and its metrics are linked from the [Wasm profile guide](../wasm/README.md); its verifier rejects transcript mutations. The Action API list extends the transport vocabulary, while the filter scenario's seven API paths and 87 observation leaves remain unchanged.
