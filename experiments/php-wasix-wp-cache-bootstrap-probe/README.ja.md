# WordPress通常起動後のRustキャッシュ接続

PHP-Wasmで固定WordPress 7.1.3を通常起動し、標準ローダーが管理下の `object-cache.php` を読む。ファイルは遅延フックだけを登録するため、コアは標準キャッシュを初期化する。起動後の試験で固定2グループの9操作をRustへ渡し、元の標準キャッシュをページ処理の前に復元する。外部キャッシュフラグの生値と、起動中に読み込んだ `alloptions` が維持されることを検証する。

Linux CIでは所有DBで最初に標準ホームを実行し、その後shimなしとshimありのホームを別プロセスで比較する。通常PHPの基準に加え、HTTPステータス・順序付きヘッダー・本文・要求コンテキスト・Rust DB RPCを照合する。接続IDを返す初期応答のバイト同一性を除き、すべてのRPC要求と応答を比較する。キャッシュは専用チャネルを閉じ、未読応答・残エントリー・予約バイトがすべてゼロになる必要がある。対象は固定要求内の操作で、共有キャッシュと任意のプラグインは別の検証範囲とする。

Windowsで派生ソースの照合、PHP構文検査、Rustのオフラインテスト62件を通過した。Linux CIでの実行は別に判定する。
